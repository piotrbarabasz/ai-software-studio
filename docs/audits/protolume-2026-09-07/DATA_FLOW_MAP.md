# UX-025 — technical data-flow inventory

Reviewed 2026-09-08 against this repository. This is an engineering inventory for the owner/legal review, not an approved privacy notice. Production settings, provider contracts and retention have not been verified. No consent requirement or public legal text changes in this checkpoint.

| Flow | Data and destination observed in code | Lifetime / logging established by code | Still requires confirmation |
| --- | --- | --- | --- |
| Page/assets | Browser requests HTML, scripts, styles and public assets from hosting; network infrastructure receives connection metadata and request URL | No application database for visits. Frontend `nginx.conf` does not disable inherited access logging; do not claim that no visit logs exist | Effective nginx/Cloud Run/load-balancer logs, fields, retention, access, location and processors |
| Contact form | Name, email, optional company, project type, optional budget, message, consent, honeypot and allowlisted service context go through `ContactApiService` to `POST /api/contact` | Form state is in component memory; code does not persist submissions to browser storage. Browser autofill/session restoration is outside that guarantee | Actual purpose, necessary fields, legal basis and consequence of not providing each field |
| Contact API | Validates and normalizes request; adds submission time. Honeypot submissions return 202 without SMTP | App logs acceptance/rate-limit/delivery/validation events, not message bodies. Validation response retains only loc/msg/type. Delivery failure records exception class, not provider body | Actual deployed logging configuration, monitoring and upstream request capture |
| Abuse limiter | SHA-256 of `request.client.host` is an in-memory key; timestamps track attempts | Per-process cap 10,000 keys; idle cleanup uses max(window, 300 seconds), triggered on requests at 30-second intervals or capacity pressure. Evicts oldest key at capacity; process exit clears memory. This is not a guaranteed deletion deadline | Trusted client-address path in deployed proxy chain. Uvicorn explicitly disables proxy headers; a proxy address may be the key. A hash is not a claim of anonymous data |
| SMTP | Form values plus time are sent to configured recipient; email address also becomes Reply-To | SMTP timeout 10 seconds, configured STARTTLS/authentication. App has no contact database; successful handoff does not prove inbox delivery | Real host, recipient/from addresses, TLS settings, mailbox access/retention/deletion, provider contracts and transfers (B-006/B-005) |
| Existing knowledge simulation | Prepared questions/answers and locally matched user input in `/demo-ai` | No question API/provider request or app storage; reset clears component state | Physical accessibility testing remains separate; infrastructure still receives page requests |
| Source example | Three manually prepared selections, quotations and public document sections on the RAG landing | No free-text input, provider or interaction request. Document JSON is a public asset; deliberately contains no customer data | Maintain provenance/version when public source content changes |
| Offline RAG foundation | Operator-selected local corpus and evaluation questions; dormant Python service can accept an explicitly supplied provider | No API route, provider adapter, credentials, database or deployment environment setting. Evaluation writes local aggregate and per-case synthetic results | Before activation: destination/model, purpose/basis, retention, transfers/contracts, spend cap, distributed abuse control and UI disclosure (B-002/B-005) |
| Analytics/calendar | No active analytics event pipeline or external booking integration in current app | No implementation from which to infer provider retention; build validation rejects prohibited analytics scripts | Owner's tool/slots decision and data review before introducing either flow |

## Required owner/legal decisions before a public privacy revision

1. Confirm administrator identity and a genuinely usable correspondence address; the build-time legal object is not evidence of verification.
2. Assign a purpose and reviewed legal basis to contact handling, abuse protection, hosting logs and each future demo/measurement/booking flow. Decide the consent requirement consistently for frontend, API and tests.
3. Record actual recipients/processors, access and contracts, hosting/mail/model locations and any transfers. Confirm operational deletion/retention settings, including mailbox backups and logs.
4. Explain required versus optional fields and rights/contact process in the public notice after review. Do not infer that lack of cookies means lack of processing, or introduce a banner without an established need.
5. Revisit this map before connecting RAG, CRM, voice, a calendar or analytics. Remove local-only copy before any question is transmitted externally.
